## 4. العيوب الهيكلية المطلوب معالجتها بالأولوية
### P0 — تنظيم المنصة حول مهمة لا حول أقسام تقنية
- قائمة رئيسية محدودة وواضحة: **الرئيسية، البوتات والأتمتة، المحادثات، العملاء، الحملات، التقارير**. تظهر **القنوات/التكاملات/الإدارة** في سياقها أو مجموعة إعدادات منظمة. لا نحذف أي وظيفة.
- اختيار البوت واضح ومستمر في عنوان مساحة العمل. أي تعديل يجب أن يبين البوت المقصود وقناته وحالة نشره.
- صفحة كل وحدة تبدأ بإجراء واحد بارز ومحتوى فعلي، لا بنصوص دعائية ثابتة وكروت واسعة متكررة.

### P0 — مصمم بصري حقيقي شديد البساطة
- مسار البداية: افتح بوتًا ← يظهر **Start / Trigger** واضح ← اضغط + فتظهر قائمة المكونات المناسبة ← أضف رسالة، زر، شرط، جمع بيانات، موظف ← المعاينة ← احفظ المسودة ← انشر بعد فحص الأخطاء.
- canvas يستحوذ على معظم الشاشة؛ مكتبة مكونات يسار/يمين وفق RTL موحد، وInspector سياقي لا يزاحم الصفحة إذا لم تحدد عقدة.
- «المحرر البسيط» و«المصمم المتقدم» يعرضان **التعريف المحفوظ نفسه** بلا تحويل فاقد، وبلا إعادة إدخال.
- النشر ليس زرًا مطابقًا شكليًا للحفظ: الحفظ إجراء دائم متاح؛ النشر إجراء مميز يحتاج فحصًا ومراجعةً واضحة، مع حالة Published/Draft/Unsaved.
- التفرعات والخطوط وحجم العقد والتكبير/التمرير وحالات المخطط المزدحم تُقبل بتفاعل فعلي لا بمجرد ظهور canvas.

### P0 — إنشاء بوت من نقطة بدء واحدة
- زر رئيسي «إنشاء بوت» ثم اختيار هدف أو قالب أو إنشاء فارغ، لا ثلاث رحلات متوازية للمبتدئ.
- في دقائق قليلة، المستخدم يكتب ترحيبًا وثلاثة أزرار، يجمع اسمًا وهاتفًا، يجرّب بوتًا في محاكي هاتف، ثم يحفظ نسخة مستقلة.
- لا يوهمه أي نص بأن التجربة داخل المحاكي رسالة حقيقية أو أن القناة مرتبطة.

### P1 — واجهة المحادثات والعملاء
- Desktop: قائمة محادثات قابلة للبحث والفرز، منطقة رسائل مركزية، ملف عميل سياقي. Mobile: رحلة واضحة بين القائمة والمحادثة والملف.
- حالات الاستلام/التسليم للبوت/التعيين/الرد/الملاحظة مميزة؛ الملاحظة **لا تُرسل خارجيًا**.
- حفظ المسودة عند تبديل المحادثة وتحديث أذونات الإرسال بناءً على الموظف الحالي.

### P1 — الحملات/CRM/المكتبات
- الحملات: القناة ← الجمهور المؤهل/المستبعد ← المحتوى ← الجدولة ← مراجعة نهائية؛ لا إرسال حقيقي دون مزود وموافقات لازمة.
- العملاء: جدول/بطاقات مدمجة، بحث وفلاتر محدودة، حالات واضحة، بيانات عميل وسجل محادثات حقيقيان.
- الكتالوج والوسائط: **القائمة أولًا**، والإضافة/التعديل في نافذة أو شاشة جانبية موحدة؛ عمليات رفع/فحص الملفات واضحة وغير مضللة.

### P1 — نظام تصميم واحد من المصدر
- تقليل CSS override وإعادة بناء هياكل الصفحات كمكونات/وحدات مفهومة بدل ترقيبات DOM المتفرقة.
- مقاييس واضحة لارتفاع رأس الصفحة، عرض القائمة، أحجام النص والأزرار، مسافات الصفحات، الرسائل، حالات التحميل/الخطأ/الفراغ.
- اتساق كامل عربي/RTL على 1366/768/390/320 و200% zoom؛ لوحة مفاتيح وتركيز واختبار وصولية.

## 6. اختبارات القبول المطلوبة قبل أي إعلان «شبيه بمنصة عالمية»
1. **مبتدئ جديد** ينشئ بوتًا مستقلًا دون مساعدة: هدف ← قالب ← ترحيب ← ثلاثة أزرار ← اسم وهاتف ← شرط ← تحويل موظف ← محاكاة كل فرع ← حفظ ← إعادة تحميل ← التأكد من نفس التعريف. سجل الوقت والنقرات والأخطاء ومواضع التردد.
2. **موظف محادثات** يبحث عن عميل، يستلم المحادثة، يراجع بياناته، يضيف ملاحظة داخلية، يكتب ردًا ثم ينتقل لمحادثة أخرى ويعود؛ لا فقد لمسودة الرد، ولا إرسال الملاحظة للعميل.
3. **صاحب شركة** ينشئ بوتين ثم يغيّر أحدهما وينشره ويتأكد أن الثاني لم يتغير؛ ويفهم معنى «مسودة/منشور/قناة متصلة».
4. **مسار متشعب** 30–50 عقدة، تجربة RTL وسحب/توصيل وتعديل مخارج الخطوط دون تراكب يمنع القراءة أو النقر.
5. **الحملة** إعداد مسودة مع مراجعة جمهور موافق عليه وحالات استبعاد، دون أي إرسال خارجي، وتأكيد فارق الحفظ عن الإطلاق.
6. **الصفحات كلها** تسجيل جلسات Desktop 1366×900، Tablet 768×1024، Mobile 390×844 و320×700، Zoom 200%، لوحة مفاتيح، معاينات/أخطاء/تحميل/حالات فارغة.
7. **تجربة اعتماد بشري**: يعرض التصميم الفعلي للمستخدم ويقيّمه قبل دمج تعديل UI جديد. نجاح الاختبارات البرمجية وحده غير كافٍ.

## 7. ترتيب التنفيذ المقترح — دفعة تصميمية موحدة لا ترقيعات
**الحزمة الأولى (P0):** Information Architecture + صفحة البوتات والمعالج + المصمم البصري/البسيط + محاكي + حالات الحفظ والنشر. هذه هي تجربة المنتج الأساسية التي سيحكم بها العميل عليه.  
**الحزمة الثانية (P1):** Inbox/CRM + الحملات + القنوات + الكتالوج/الوسائط + التحليلات؛ نفس Design System وسلوك النماذج.  
**الحزمة الثالثة (P1 Quality):** باقي الإدارة والتكاملات + اختبارات قابلية الاستخدام والوصولية/الأجهزة + فحص اتساق بعد الدمج.

**شرط العمل:** لا تغيّر قواعد العمل/عقود API/DB/الصلاحيات، لا تفعل مزودًا خارجيًا، لا ترسل رسالة عميل، لا تفترض أن لقطات المنافس صور لإصدارنا، ولا تنسخ أصول المنافس. المطلوب تنفيذ أنماط تفاعل احترافية بهوية Elhafez المستقلة.
