## 3. دليل BotSailor العملي الأهم

- إنشاء Flow، فتح Start، قائمة مكونات من مخرج العقدة، إضافة Text/Interactive/Button/User Input/Condition، معاينة خصائص؛ صور `001`–`015`.
- ظهرت بنية 12 عقدة و11 وصلة قبل الحفظ الأخير، بينها فرعا True/False؛ `016`.
- حذف وصلة ثم Ctrl+Z واستعادتها؛ `017` + سجل التفاعل.
- فشل حفظ بعد نجاح أول، ثم أعيد فتح 10 عقد و9 وصلات؛ `018`، `019`، `031`، `032`. سبب الفشل غير مثبت.
- Mixed Template وPreview والتحقق من الاسم ثم تعارض تسمية Save Draft/Submitted؛ `033`–`035`. دلالة Submitted الخارجية غير مثبتة.
- Quick Actions وSequences وWebhook وUser Input Campaign وAI والإعدادات؛ `036`–`042` (معظمها **عُرض** ولم يعمل على قناة حقيقية).
- تعذر/لم يكتمل: اختبار المحادثة حتى نهاية حقيقية، إرسال وسائط أو WhatsApp Flows، Fan-in، reconnect، multi-select، Stress 50/100+، فحص كامل لـInbox/CRM/Broadcast، فحص Elhafez داخل حساب مستخدم.

## 4. التنفيذ الإلزامي — بلا ترقيع بصري

### أ. أساس المصمم والتفاعل (P0)
- Zoom to pointer مع 100% وFit وReset ومؤشر نسبة واضح، Pan بالعجلة/Space/Touch، Minimap، تنقل لموضع خطأ، دون قفز تلقائي للكاميرا عند فتح خصائص.
- سحب عقد وربطها، إظهار خط مؤقت متحرك، connect/disconnect/reconnect مع Undo/Redo وتحديد الخط؛ متانة عند إعادة ترتيب الأزرار؛ drop on empty opens compatible component picker.
- تحديد متعدد، نسخ/لصق/تكرار، محاذاة، توزيع، Auto-layout آمن، بحث داخل المخطط، اختصارات لا تعمل أثناء الكتابة، دعم اللغة والاتجاه.
- محرر رسالة مركبة ومحرر خيارات زر مرتبطين بتصرفات صحيحة حسب القناة، مع معاينة العميل، لا مجرد شكل عقدة.
- INPUT بأنواع وقواعد تحقق ومهلة/تخطي/محاولات، Typed Fields مع CRM، CONDITION بمجموعات AND/OR، فروع fallback/error/timeout، triggers والعمليات الأساسية.
- Simulator غير متصل بالخارج، يعرض Transcript + Trace + Values ويجرب جميع المسارات والحالات.
- الحفظ/الإصدارات مع Autosave آمن، Revision 409 Conflict، Fail/Retry/Local export/recovery، وعدم إظهار النجاح إلا بعد تأكيد الخادم، مع منع نشر مسار غير قابل للتنفيذ.

### ب. الميزات المتقدمة داخل نطاق F01–F36
- ساعات العمل، Smart Delay، Randomizer/A-B، HTTP API/Webhook بمرجع آمن ومخارج إخفاق، قوالب ومسارات فرعية، handoff/pause/resume، Consent/opt-out، استيراد/تصدير، تحليلات الخطوات، وقدرات كل قناة.
- AI builder وتحسين النص وWhatsApp Flows: واجهة وعقود واختبارات Mock؛ لا تُعلنها متصلة أو صالحة للإرسال دون مزود مؤهل واتصال مصرح.

### ج. نقاط تقنية تمنع الإغلاق الخاطئ
- محرك Elhafez الحالي له `FlowDefinition` قائم على `nodes` وروابط مضمّنة (`next/yes/no/choices`)، وValidators وحد 100 عقدة للمسودة العادية؛ المقترح `nodes + edges` قد يكسر المخططات القديمة. اختر طبقة توافق أو إصدار schema/adapter واضحًا، لا تسجل العقد الجديدة دون تحديث compiler/runtime/provider renderers وبقية العقود.
- قواعد حفظ وتوافق وIsolation الشركة والقنوات والأدوار لا بد من اختبارها بالخادم لا بمجرد إخفاء زر.
- حد 500 عقدة مقترح كـStress acceptance بينما Validation الحالي يحد التصميم العادي عند 100؛ وثّق قرار دعم 100 أو رفعه بصورة مدروسة. لا توهم بأن اختبار 500 قابل للحفظ بالصيغة الحالية.
- تجنب تضاعف layers الخاصة بـ`vessel.css`/`flow-builder.css`؛ اعمل بنظام تصميم موحد وبنية Frontend مفهومة.
- لا تدمج ما نُفذ من خصائص موجودة (draft/version, undo, templates, palette) داخل نسخ ثانية متوازية؛ حسّن الموجود أو استبدله باستراتيجية ترحيل مؤكدة.
