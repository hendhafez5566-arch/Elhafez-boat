# F26 — secure incoming assets, 2026-10-21

Migrations0044/0045 add conversation-private assets to existing chatbot_media and a source retrieval queue. No parallel bot engine or scanner. Authenticated, verified channel parsers enqueue account/channel/source-bound references idempotently. Provider downloads are OFF by default (`INBOUND_MEDIA_FETCH_ENABLED=0`); no real account, fetch, message or provider activation was used. Offline transports qualify code contracts, not live account readiness.

WhatsApp metadata must match the received media ID, declared size and MIME; only lookaside.fbsbx.com may receive its bearer. Telegram getFile must match received file ID and size, with bounded traversal-free path on api.telegram.org. Messenger/Instagram source URLs must belong to fbcdn.net/fbsbx.com; no token is sent to their CDN. All binary HTTP uses HTTPS, exact selected host, pinned all-public DNS, 12-second total deadline including lookup, no redirects/compression, declared and streamed 5MiB limit. Magic MIME, requested kind, declared size and metadata MIME are checked before storage. References are cleared on completion/failure; failed/rejected/timeout states contain only fixed reason codes. GET transaction rollback leaves a durable PENDING item safely retrievable after restart. Archived contacts cancel intake.

Website upload uses existing unguessable visitor bearer, exact origin, active contact/conversation lock and company quota. No synthetic staff actor. 5MiB accepted magic types, 5 uploads/minute and 20/day per conversation, shared atomic tenant quota. Private incoming files get no public route and never enter the outbound media library. All bytes enter PENDING quarantine. Existing real ClamAV processor alone produces CLEAN/QUARANTINED; scanner failure stays private and retryable. Visitor send accepts only its own CLEAN asset ID, then uses native typed input and existing engine/receipt deduplication. A raw URL, text JSON, foreign UUID, pending or infected file cannot become a trusted attachment. Website MEDIA triggers now correspond to the real upload/send path; LOCATION remains unsupported. Designer/preflight and explicit Mock attachment simulator use this capability.

Widget upload state stores only asset/message UUIDs per session. Reload/lost acknowledgement rechecks the scan and retries the SAME message UUID, proving one incoming message after actual server commit with response deliberately dropped. Rejection feedback survives normal message polling. CRM shows private asset and source status with CLEAN-only tenant-authenticated download, attachment/no-store/nosniff/sandbox headers. No public URL is issued. Privacy erasure removes incoming bytes/names and queued references and invalidates visitor session. Tenant privacy lock uses NO KEY UPDATE, preserving serialization while permitting FK key-share for contact-first uploads; deterministic actual race proves erasure of racing bytes without deadlock.

Retention: incoming bytes inherit the company's existing contact erasure/retention policy, not the public library lifecycle. Pending/failed/infected assets stay inaccessible; owner deletion/erasure clears content, and enabled cleanup physically removes DELETED assets after30days. Completed intake metadata is removed after90days when tenant cleanup is enabled. Pending intake remains until processing or explicit privacy erasure; disabling cleanup disables automatic deletion. Deleting a retained private asset safely nulls the intake media reference, not tenant identity. No previous authored assets or published bot snapshots are rewritten.
