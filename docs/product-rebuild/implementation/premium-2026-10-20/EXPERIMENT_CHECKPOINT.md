# First-exposure experiment comparison — 21 October 2026

Uses existing RANDOMIZER/GOAL nodes, immutable versions and committed step telemetry; no new engine, event store or migration.

Published version/experiment/goal catalog and guarded API report compare the first conversation assignment per bot/version/experiment. A repeated allocation or goal never adds a denominator/conversion. A goal must be ordered after allocation within the same pinned version and within seven days. Cross-execution ties are not treated as subsequent goals. Observation lookback is 7/30/90 days; first exposure is selected over history before applying that filter, so a recent return cannot change an old cohort. Legacy unordered allocations are excluded and explicitly counted. Configured variants with no exposure have a null rate, not a fictional zero. Mixed allocations, cohort maturity, configured weights, descriptive conversion rates and Wilson 95% intervals are displayed; this is not causal/winner or delivery attribution.

Arabic real UI includes published version, experiment, goal and period controls with desktop/mobile scrollable comparison and scoped asynchronous lifecycle guards. Authentication/tenant/bot/version/node checks are enforced by the API, and data excludes contact answers and messages. Simulator traces are not inserted by this module.

Validation: 200 units plus TypeScript/build PASS. `tests/flow-experiments-db.mjs`: 8 actual PostgreSQL scenarios (real published runtime allocations/goals; repeated callbacks/returns, prior/late goals, seven-day maturity, unknown legacy order, lookback, crossovers, immutable versions, zero samples and forced RLS/resource denial). Synthetic timestamp adjustments are explicit boundary fixtures, not production measurements. `tests/flow-experiments-browser.mjs`: 3 real Chromium scenarios using those real saved counts, zero-sample latest version and version switch on desktop/mobile.
