# Dashboard UX specification

Arabic-first, full RTL, mobile-first, accessible, high-contrast. Positive green, warning amber, negative red. Avoid pale text, cluttered filters, huge tables and long help text. Compact pagination and clear actions. Two modes: Simple for everyday staff, Advanced for owners/admins.

Navigation:
1 Home: actionable inbox, new leads, bookings, pending handoffs, availability alerts, connection status.
2 Programs: category tabs, create wizard (basics; hotels/services; pricing/capacity; preview/publish), duplicate, draft, version history.
3 Offers: eligibility, linked programs, time windows, approvals.
4 Inbox: conversation list, chat pane, customer context, notes, takeover/release, assignment, SLA.
5 Customers: CRM profile, interests, consent, history, dedup within tenant.
6 Bookings: provisional requests, review, availability verification, status and payment references.
7 Follow-ups: tasks, triggers, approved templates, stop rules.
8 Bot settings: welcome, language/tone, menu visibility/order, FAQ, AI toggle, handoff, preview simulator, publish/rollback.
9 Reports: inquiries, leads, conversions, program demand, agents, exports.
10 Employees: roles, invitations, scoped access.
11 Settings: branding, branches, hours, WhatsApp connection, subscription, privacy, audit.

UI approval must be based on actual separate screen previews, not a collage; mockups are not proof of implemented functionality.
