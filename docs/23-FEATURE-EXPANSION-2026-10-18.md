## Privacy and provider guardrails

Comment webhook handling happens only *after* the existing raw-body Meta HMAC verification. Candidate records store opaque comment IDs, chosen canned reply text, account/rule IDs and timestamps; no entire public comment is retained. Webhook replay deduplicates by company/account/comment ID. Rules never message arbitrary people who have not triggered a Meta comment event. Dispatch processes approved candidates only, within a bounded seven-day window and without repeating ambiguous attempts.

The Meta sender implements a source-side integration path but must undergo official provider permission/account acceptance before enabling in any deployment. When current Meta API requirements differ, fix and retest the adapter. A merchant must choose REVIEW vs AUTO mode; account-level permissions and legal/Meta limits take precedence.

No data is claimed to have been synced to external CRMs, social networks, or AI services.
