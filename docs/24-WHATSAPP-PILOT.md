# تجربة واتساب — دليل المالك

هذه تعليمات تحضير، وليست دليل تشغيل Staging أو نجاح Meta. لا يوجد رابط عام منشور حتى الآن.

## التشغيل المستقل

بعد موافقة المالك على الاستضافة والتكلفة والنطاق، استخدم مشروع Compose جديدًا `boat-pilot` وقاعدة وVolume جديدين؛ لا تستخدم بيانات الإنتاج. ملفا التشغيل: `deploy/compose.platform.yaml` و`deploy/compose.staging.yaml`. الأخير يضيف Caddy لإنهاء HTTPS على نطاق حقيقي يوافق عليه المالك ويوجه DNS إليه؛ لا ينشئ نطاقًا أو حسابًا.

قبل تشغيل الخدمات: جهز migration role وruntime role منفصلًا غير مالك للجداول وNOSUPERUSER/NOBYPASSRLS، وصلاحيات إدارة منصة منفصلة، ثم طبّق جميع المهاجرات الحالية بـ `npm run db:migrate`. لا تستخدم سكربت صلاحيات CI في Staging؛ صلاحياته واسعة عمدًا لاختبار قاعدة مؤقتة. جهز حساب المالك عبر سكربت bootstrap في بيئة مشغل موثوق، واحتفظ بكلمة المرور خارج Git والتقارير. لا توجد كلمة مرور عامة.

اضبط DATABASE_URL وPLATFORM_DATABASE_URL، مفاتيح التشفير المنفصلة، RATE_LIMIT_SECRET، APP_PUBLIC_ORIGIN وMEDIA_PUBLIC_ORIGIN على HTTPS، وMETA_APP_ID وMETA_GRAPH_VERSION. احتفظ بمفاتيح التشفير الأصلية في نسخة احتياطية منفصلة عن قاعدة البيانات. لا تضع قيم الأسرار في أوامر مشتركة أو سجل المحادثة. اضبط TRUSTED_PROXY_IPS بعناوين gateway الدقيقة فقط بعد فحص الشبكة؛ الافتراضي الفارغ لا يثق بترويسات العميل. أضف ClamAV وsocket فعليًا إذا كانت تجربة رفع الوسائط مطلوبة؛ الوسائط PENDING تبقى خاصة عند غيابه. إعداد socket وحده لا ينشئ scanner.

بعد التحضير والموافقة: شغّل `docker compose -p boat-pilot -f deploy/compose.platform.yaml -f deploy/compose.staging.yaml up --build -d`. هذا أمر نشر خارجي لا يُنفذ قبل الموافقة. شغّل `node scripts/ops-health.mjs` من سياق آمن، وافحص health وTLS والعزل والاستعادة قبل السماح بالإرسال. لا تستخدم `down -v` أو reset.

## ربط الرقم بأقل خطوات

1. افتح لوحة الشركة ← ربط واتساب. في Meta أكمل بنفسك تسجيل الدخول وإضافة رقم التجربة والتحقق من ملكيته؛ وافق صراحة وقت هذه الخطوة. لا تشارك OTP أو كلمة المرور هنا.
2. في بيئة الخادم الآمنة يضبط المشغل META_APP_SECRET وMETA_WEBHOOK_VERIFY_TOKEN. داخل إعدادات Meta اضبط callback على رابط Staging الحقيقي متبوعًا بـ `/api/v1/whatsapp/webhook`، وفعّل أحداث `messages` واشترك بالتطبيق الصحيح في WABA. لا يلغي زر الفصل المحلي اشتراك Meta.
3. داخل نموذج المنصة فقط أدخل Phone Number ID وWABA ID وAccess Token بصلاحيات WhatsApp messaging/management اللازمة، واضغط التحقق والربط ثم فحص الاتصال الآن. يحتفظ الخادم بالرمز مشفرًا؛ لا يرجعه إلى المتصفح. التشخيص يقرأ الحساب والاشتراك ولا يفعّل اشتراكًا بالنيابة عنك.
4. احفظ البوت وانشره، ثم أرسل من رقم آخر تملكه. نجاح قراءة الرقم أو الاشتراك لا يثبت التسليم؛ راقب Inbox وCRM والإيصال الحقيقي.

## قبول فعلي إلزامي

سجل التوقيت ومعرفات رسائل غير سرية وحالات sent/delivered/failed، مع لقطة آمنة بلا أرقام كاملة أو أسرار. اختبر النص والأزرار والقائمة والمحتوى المنشور والسؤال والحقول وCRM والتحويل والرد اليدوي والاستمرار بعد إعادة التشغيل وSTOP وحظر التسويق وخارج 24 ساعة وتكرار webhook والفشل. لا ترسل إلى أشخاص آخرين. لا تعد إرسال UNCERTAIN دون إثبات عدم الإرسال. محاكاة Meta لا تحقق أيًا من هذه البنود كقبول حي.

المساعد الحالي يعرض معلومات معتمدة وخطة نية محدودة؛ لا يدّعي تنفيذ وكيل مستقل. تعليقات المنصات الأخرى وإرسالها غير مطلوبة ولا تُفعّل في التجربة.
